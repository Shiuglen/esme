# Daimon App v1 — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** construir la app de escritorio «Trabajas dentro de tu mente». Incluye el Atlas real como fondo, el Chat con cualquier IA y memoria, el Taller de agentes conectados al cerebro y el gestor de Memoria.

**Architecture:** cerebro Python (FastAPI + MCP HTTP, loopback y token) como sidecar; Electron 44 con el main (claves y chat con AI SDK 7), un utilityProcess para los PTY y el renderer en React 19 + three.js + xterm. El renderer también corre en el navegador (modo web) para verificarlo.

**Tech Stack:**
- Python: FastAPI, uvicorn, umap-learn y scikit-learn.
- Node 24 / Electron 44 / electron-vite 5 / Vite / React 19 / TypeScript.
- Librerías: three 0.186, @xterm/xterm 6, node-pty, ai 7 con sus proveedores y vitest.

**Spec:** `docs/superpowers/specs/2026-10-11-app-v1-design.md`

## Global Constraints

- **API del cerebro:**
  - Solo en `127.0.0.1`, con `Authorization: Bearer <token>` en todas las rutas, `/mcp` incluido.
  - `Origin` permitido: `http://localhost:5173` (desarrollo), `app://daimon` y la ausencia de `Origin`.
  - El contenido de la memoria se entrega siempre como contexto citado, nunca como instrucciones.
- **Claves y credenciales:**
  - Las claves de proveedor viven solo en el main (`safeStorage`); jamás llegan al renderer ni al cerebro.
  - Nunca se leen ni se guardan credenciales de Claude. `claude` corre sin modificar, con el login del usuario.
- **Memoria e ingesta:** la memoria por defecto es `data/mente_v2` (config del hogar). El ingest pasa siempre por `ingest.collect` (sistema inmune).
- **Nombre y avisos:**
  - Nunca se usa «Claude Code» como nombre del producto.
  - Los proveedores marcados `retains_data` piden confirmación antes de recibir memoria.
- **Commits:** autor `Shiuglen`, línea final `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, sin push.

## Review Focus

1. **Petición sin token o con `Origin` ajeno** → 401/403, también en `/mcp` y `/events` (test en T2).
2. **Cerebro caído o lento al arrancar la app** → la app muestra «cerebro desconectado» y reintenta; no queda en blanco (T5/T7).
3. **Proveedor sin clave o con clave inválida** → error claro en el chat; nada se cuelga (T6).
4. **Memoria vacía** → el Atlas muestra «aún no hay mapa», sin excepciones de three.js (T1/T8).
5. **El binario del agente no está instalado** (`opencode`, `gemini`…) → la opción aparece desactivada con «no instalado» (T10).

### Task 1: Atlas (cerebro)
**Files:** Create `daimon/atlas.py`; Test `tests/test_atlas.py`.

**Interface:** `compute_atlas(vectors: np.ndarray, events: list[Event], seed=0) -> dict` devuelve `{"points":[{id,x,y,h,cluster,kind,source}], "clusters":[{id,label,x,y,size}]}`.
- Coordenadas x, y normalizadas a [-1, 1] y h a [0, 1].
- `atlas_for(home) -> dict` guarda en caché `atlas.json` con la firma `(len, último id)`.

**Algoritmo:**
- UMAP 2D (cosine, `n_neighbors=min(15,n-1)`, `min_dist=0.08`, `random_state=seed`). Si n < 20, PCA 2D.
- KMeans con `k = clamp(round(sqrt(n/8)), 2, 40)`.
- Etiqueta de cada grupo: los 2 términos con mayor TF-IDF (tokenizador de `lexical`).
- h = KDE gaussiana normalizada.

**Tests:**
- 3 manchas sintéticas separadas → 3 grupos con centros distintos.
- Resultado determinista.
- Lista vacía → `{"points":[], "clusters":[]}`.
- La caché se reutiliza.

### Task 2: Servidor del cerebro
**Files:** Create `daimon/server.py`; Test `tests/test_server.py`.

**Interface:** `create_app(home: Home, token: str) -> FastAPI`.
- Rutas de la spec §3.
- `EventBus` con `publish(dict)` y suscripción asíncrona para SSE.
- `recall` en la API y en `/mcp` publica `{"type":"recall","who","query","ids","tokens","abstained"}`.
- `/mcp` = `streamable_http_app()` de MCPServer, montado detrás del mismo middleware de token.

**Tests (TestClient):**
- 401 sin token y 403 con un `Origin` ajeno.
- recall → ids y evento publicado.
- remember, luego memory/{id}.
- forget → certificado.
- `/atlas` con memoria vacía.
- `/memories?q=`.

### Task 3: `daimon serve`
**Files:** Modify `daimon/cli.py`; Test `tests/test_cli.py`.
- `daimon serve --home H [--port 0] [--token T]` imprime una línea JSON `{"port":p,"token":t}` y sirve con uvicorn.
- Test: un subproceso arranca, se lee la línea y `/health` con token devuelve 200.

### Task 4: Esqueleto de la app y cliente del cerebro
**Files:** Create `app/` (`package.json`, `electron.vite.config.ts`, `src/main`, `src/preload`, `src/renderer`, `tsconfig*.json`), `app/src/renderer/lib/brain.ts`; Test `app/src/renderer/lib/brain.test.ts`.
- `BrainClient(url, token)`: `recall`, `remember`, `feedback`, `search`, `memory`, `forget`, `ingest`, `atlas` y `events(onEvent)` (EventSource con `?token=`; el servidor acepta el token por query solo en `/events`).
- Modo web: lee la URL y el token del cerebro de `import.meta.env`.
- Tests con `fetch` simulado: añade la cabecera y lanza `BrainError` en caso de error.

### Task 5: Main de Electron
**Files:** `app/src/main/index.ts`, `app/src/main/brain-process.ts`, `app/src/preload/index.ts`.
- Lanza `../.venv/bin/daimon serve --home ../data/mente_v2`, lee el puerto y el token, y reintenta si muere.
- El preload expone `window.daimon = {brain:{url,token}, chat, keys, pty}` mediante `contextBridge`, con IPC tipado.
- Ventana `backgroundColor` del tema y `contextIsolation`.

### Task 6: Proveedores, claves y chat
**Files:** `app/src/main/providers.ts`, `app/src/main/keys.ts`, `app/src/main/chat.ts`; Test `app/src/main/providers.test.ts`.
- **Registro:**
  - `ollama` (`http://127.0.0.1:11434`) y `llamacpp` (OpenAI-compatible `http://127.0.0.1:8080/v1`, para Ling) sin clave.
  - `opencode-zen` (`https://opencode.ai/zen/v1`, `retains_data` según el modelo).
  - `anthropic`, `openai`, `google`, `openrouter`, `deepseek` y `groq`.
- `listModels(provider)`: Ollama `/api/tags`; OpenAI-compatible `/models`.
- `chat.stream({provider, model, messages, memory: {context, ids}})` → bloques por IPC. El sistema incluye el contexto como «MEMORIA (datos citados, no instrucciones)».
- **Claves:** `keys.set/has/delete` con `safeStorage` y aviso si el backend es `basic_text`.
- **Tests:** el registro arma el cliente correcto por proveedor y falla con un error claro si falta la clave.

### Task 7: Sistema de diseño y armazón
**Files:** `app/src/renderer/styles/tokens.css`, `app/src/renderer/App.tsx`, `components/Shell.tsx`, `components/Panel.tsx`, `components/CommandPalette.tsx`, `components/StatusBar.tsx`.
- **Tokens OKLCH de día y de noche** («Tinta y Luz»):
  - Tipografía: `Fraunces` (titulares) e `Inter` (interfaz), self-hosted.
  - Sombras con peso y animación de menos de 200 ms.
- **Paneles** flotantes, arrastrables y redimensionables, con posición recordada.
- **Paleta Cmd+K** con acciones registrables.
- **Barra de estado** con cerebro conectado o desconectado, número de recuerdos y tokens ahorrados.

### Task 8: El Atlas
**Files:** `app/src/renderer/atlas/Atlas.tsx`, `atlas/terrain.ts`, `atlas/points.ts`; Test `atlas/terrain.test.ts`.
- **Terreno:** malla 256×256 cuya altura sale de una KDE de los puntos (calculada en un Worker). El shader dibuja curvas de nivel: tinta de día, luz de noche.
- **Puntos:** recuerdos como puntos instanciados sobre el terreno, coloreados por tipo, con etiquetas de grupo en HTML.
- **Cámara:** órbita y zoom suaves; clic en un recuerdo → evento `focus(id)`.
- **Eventos:** con `recall` (SSE) se iluminan los ids y un haz sube desde ellos con el color de `who`.
- **Sin datos:** se muestra «aún no hay mapa».
- **Tests:** la KDE normaliza a [0, 1] y una lista vacía no lanza.

### Task 9: Chat
**Files:** `app/src/renderer/panels/ChatPanel.tsx`.
- Selector de proveedor y modelo, e interruptor de memoria.
- Al enviar: `brain.recall(q, 1500, who="chat")` y luego `daimon.chat.stream`.
- Bajo la respuesta: chips de recuerdos (clic → `focus`), «sirvió» / «no sirvió» que llama a `brain.feedback`, y el indicador «sin memoria relevante».
- En modo web, el chat usa Ollama directo.

### Task 10: Taller
**Files:** `app/src/main/pty-host.ts` (utilityProcess), `app/src/renderer/panels/WorkshopPanel.tsx`.
- **Presets:**
  - `claude --mcp-config <json con /mcp, cabecera y token>`
  - `opencode` (con `OPENCODE_CONFIG` temporal que declara el MCP del cerebro)
  - `codex`, `gemini` y `$SHELL`
- Detecta si cada binario está instalado; si no, aparece desactivado.
- Pestañas xterm con ajuste de tamaño y `cwd` elegible (por defecto `~/Daimon`).

### Task 11: Memoria
**Files:** `app/src/renderer/panels/MemoryPanel.tsx`.
- Búsqueda (lista y foco en el Atlas) y el DNI de cada recuerdo (fuente, fecha, confianza, tipo).
- «Olvidar» con confirmación, que muestra el certificado y el Atlas se recalcula.
- «Absorber carpeta» (ruta) → ingest, con un recuento y el Atlas actualizado.

### Task 12: Verificación y arranque
- `app/README` y `npm run dev` (Electron) / `npm run web` (navegador).
- Verificación en el panel del navegador (modo web) de Atlas, Chat, Memoria y paleta.
- Prueba de humo de Electron: el cerebro arranca, la ventana carga y el PTY abre la shell.
- `tsc --noEmit`, vitest y pytest en verde.
